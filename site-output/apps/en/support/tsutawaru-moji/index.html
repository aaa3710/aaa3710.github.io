Last updated: September 5, 2026

Tsutawaru Moji turns face-to-face conversation into large, readable text on iPhone. Its wide input surfaces can listen while held or start and stop with taps. Hold to Talk is the default.

Requirements
  • iPhone: iOS 17 or later
  • Apple Watch input: watchOS 10 or later and a paired iPhone
  • Display languages: System, Japanese, or English
  • Spoken transcription languages: Japanese or English

Display language and spoken language are separate settings. The App does not translate between languages.

Get started
  1. Open Settings & History. Choose One, Two, or Three iPhone input areas, then confirm the interaction style, each button’s transcription method, spoken language and question-mark setting, and the text size.
  2. Start with On Device, which needs no API key.
  3. Return to the main screen. In Hold to Talk, hold an input surface while speaking. In Tap to Start/Stop, tap an input surface once and then speak.
  4. When finished, release in Hold to Talk or tap the same input surface again in Tap to Start/Stop. In Hold to Talk, the same recording ends normally even if your finger has moved outside the input surface.
  5. Finalized text is saved automatically in history on the iPhone. Audio is not saved in history.

With VoiceOver, double-tap the input surface to start and double-tap again to stop.

On-device transcription

On Device is the default. It needs no OpenAI API key or OpenAI API payment and does not send conversation audio to OpenAI. It uses only Apple on-device speech recognition on a supported iPhone and does not silently switch to an external method when unavailable.

Choose one of these display behaviors:

  • All at the End: shows the finalized result after recording ends
  • Show While Recognizing: shows a changing unconfirmed ending; only finalized text is saved to history

The App conservatively removes a limited set of standalone Japanese and English hesitation words in every transcription method. There is no setting to turn this behavior off.

For On Device with All at the End, supported devices can optionally edit the finalized transcript with Apple Intelligence. The transcript and button-specific instructions do not leave the device. If the feature is unavailable, fails, or returns an empty result, the App keeps the unedited transcript.

If on-device recognition is unavailable, check installed speech assets for the selected language, Microphone and Speech Recognition permissions, and device support.

OpenAI API and Hybrid transcription (optional)

OpenAI modes use an API key that you provide. The first time you select OpenAI API or Hybrid, read the current explanation of what is sent, the recipient, costs, OpenAI’s handling, and how to withdraw, then explicitly consent. If consent is missing, damaged, for an older explanation, or withdrawn, the App changes every affected input surface to On Device and does not begin OpenAI recording or transmission.

OpenAI API sends the completed recording directly from iPhone to OpenAI after you stop and then displays the completed transcript. Hybrid shows an on-device draft while recording, sends the same utterance to OpenAI only after you stop, and replaces the draft with the finalized result on success. Neither mode streams audio to OpenAI while recording or displays partial OpenAI captions.

  • You are responsible for OpenAI API charges and network data charges
  • A ChatGPT subscription and OpenAI API billing are separate
  • The App developer does not sell or manage API keys, API credits, billing, or usage limits
  • Upload audio is 24 kHz, mono, 48 kbps AAC. This is a speech-focused product setting, not a published OpenAI maximum
  • The maximum recording setting is 1, 2, 3, 5, or 10 minutes, or No Limit. It does not apply to On Device

Downloading from the Japan storefront does not make processing Japan-only. The destination is the global api.openai.com endpoint, and the App does not guarantee that submitted content is processed or stored only in Japan.

You can withdraw consent at any time in Settings. Withdrawal changes every input surface to On Device and prevents future OpenAI recording and transmission. It does not automatically remove the API key; use the separate key-removal action if the key is no longer needed.

Stopping a request that has already begun is best effort; submitted information and charges already incurred cannot be recalled. Downloading from the Japan storefront does not limit OpenAI processing to Japan.

Do not send medical information, authentication information, financial information, or other highly sensitive content through an OpenAI mode. Anyone under 18 needs permission from a parent or legal guardian to use an OpenAI mode. Do not send audio or other personal information of children under 13 using this app’s OpenAI modes, including recordings made by an adult.

The API key cannot be saved

  • Confirm that the iPhone has a device passcode. The App cannot save a key without one.
  • Use an OpenAI project key dedicated to this App. Where available, restrict it to transcription and set a usage limit.
  • Never send the key to another person, chat, email, ordinary note, or support request.
  • OpenAI recommends keeping API keys out of mobile apps and protecting them behind a backend. The App’s serverless BYOK design cannot provide equivalent security.
  • If the App cannot confirm removal of an older Keychain item after reinstallation, it does not use the remaining key or start OpenAI recording or transmission. Unlock the device and choose Check Again, then restart if needed. If it persists, contact support without sending the key.

See OpenAI’s API key safety guidance.

Spend alerts alone do not stop API traffic. To stop based on spending, check an enforced hard spend limit in OpenAI settings. Enforcement can be delayed and spending may slightly exceed the configured amount. The App does not control billing. See OpenAI’s spend limits guide.

OpenAI mode fails

Follow the message in the App and check:

  • Whether the API key has been revoked
  • Whether the model is available to the OpenAI Project
  • OpenAI API balance, usage limits, and Usage
  • The iPhone’s internet connection
  • OpenAI service status

OpenAI API mode does not automatically switch methods or resubmit audio after a failure. Hybrid uses a trustworthy finalized on-device result only if one is available and displays the reason; otherwise it discards the draft. Do not attach an API key or recording to a support request. If needed, send only the displayed error information that contains no secret.

If you see a warning that temporary audio could not be deleted, a file may remain in a protected, App-specific area. The App retries deletion on the next launch and warns again if that launch sweep also fails. Do not assume the file has been deleted. If the warning continues, contact support without sending a secret or recording.

OpenAI data usage

From the OpenAI API section in Settings & History, view sent bytes, received bytes, and API request count for Today, 7 Days, 30 Days, or a custom date range. Cellular, Wi-Fi and Other, and Unknown are separated.

These values come from the OpenAI API HTTP bodies and headers that iOS reports to the App. For one logical API request, transfers from redirect and retry transactions are added together, and 4xx and 5xx responses are included when metrics are available. Bytes transferred before cancellation are recorded; a pre-transfer cancellation with zero bytes is not.

If one logical request uses both Cellular and Wi-Fi and Other, it appears once in each interface row but once in the overall API request count. Interface-row counts therefore may not add up to the overall count. The totals exclude TLS overhead, transport overhead, operating-system retransmissions, other apps’ traffic, and the amount billed. They are not expected to match OpenAI Usage or a carrier bill exactly.

Data-usage records stay on the iPhone for up to two years and can be erased from this screen. If saving fails, the App warns that the displayed values may be lost after relaunch. If erasing fails, it keeps the on-device records and shows a warning rather than appearing to succeed. Erasing them does not change transcript history or OpenAI-side Usage and billing.

Speak from Apple Watch (experimental)
  1. On iPhone, set Input Device to Automatic or Apple Watch only in Settings & History.
  2. In Apple Watch Transcription Settings, choose One, Two, or Three input areas and confirm the interaction style and each button’s settings.
  3. Keep both the iPhone app and Watch app open in the foreground.
  4. Confirm that the iPhone shows the Watch as connected with settings applied.
  5. In Hold to Talk, hold a Watch input surface while speaking and then release. In Tap to Start/Stop, tap once to start and tap the same surface again to stop.

The Watch shows an audio level and sends 16 kHz PCM audio chunks to the paired iPhone as they are captured. “Near real time” describes this audio transfer; it does not mean partial OpenAI captions are displayed. The iPhone performs transcription, displays the result, and saves history.

When Apple Watch only is selected, the iPhone input surface is disabled for both touch and VoiceOver and tells you to start from the Watch. Select Automatic or iPhone only if you also want to start input on iPhone.

With VoiceOver on Apple Watch, activate the audio-input surface once to start and again to stop. It does not start while disconnected or processing.

If the connection drops, a chunk is missing or out of order, or transfer cannot keep up, the whole recording is discarded rather than displaying potentially misleading text. If the devices do not connect, check that:

  • The Watch is paired to this iPhone and the Watch app is installed
  • Both apps are in the foreground and show that they are reachable
  • Another recording was not already started on iPhone
  • Bluetooth, Wi-Fi, and the iPhone-Watch connection are available
Share with Nearby iPhones (experimental)

This feature sends text only from one speaking iPhone to up to seven viewing iPhones (eight devices total) over a nearby direct connection. It does not send audio, saved history, or API keys and uses no developer server, CloudKit, or user account.

Connect

  1. Tell every participant that audio will be recorded and transcript text shared, and obtain permission. On every speaker and viewer device, explicitly confirm that all participants have agreed.
  2. On the speaking iPhone, choose Speak & Send Text.
  3. On a viewing iPhone, choose View Someone's Text and select the speaker.
  4. The speaker confirms that the invitation is from the person in front of them, then accepts it.
  5. Compare the six-digit code shown on both devices face to face and confirm a match on both. No transcript text is sent or accepted until both confirmations are complete.
  6. The speaker chooses Back to Transcription and keeps every participating app in the foreground. Use Stop Sharing or Stop Viewing to end the role.

The six-digit code compares the two devices in that connection; it does not prove a person’s identity. Verification fails closed when multiple peers have the same display name. Local Network permission is required. The operating system manages the connection path, and the App requires session encryption. While connected, the sharing symbol on the main screen opens the verified/pending peer count and the explicit stop action.

If the App reports that two devices have the same number, fully close the App on both iPhones, reopen it, and connect again. Stopping sharing alone does not change the number assigned for that launch.

The App cannot prevent recipients from taking screenshots or photos, copying text, or sharing it again. Ending sharing may not recover information they have kept. Check the recipient and content before sharing.

The connection ends when an app enters the background. The feature does not support remote locations, replaying history to a later participant, background use, eight or more viewing devices (nine or more devices total), or reliable large-venue broadcasting.

Changing the display language ends sharing on that device so the peer name cannot remain in the previous language. Follow the message in the App and connect again. The launch-specific anonymous number stays the same.

The current direct connection prioritizes sending text to a small group in the same place without adding a server or account. Apple marks the MultipeerConnectivity APIs used here as deprecated in its documentation as of August 21, 2026, so the App will not build large-scale delivery on this path. Expanding to eight or more viewers, remote use, or asynchronous use would require a fresh evaluation of Network.framework, CloudKit/CKShare, or Group Activities for the specific use case. Work should resume only after any account, storage, cost, and privacy changes are disclosed and security and recovery can be validated across multiple physical devices.

History and deletion
  • Finalized text, time, and transcription method remain only on the iPhone
  • Audio is not saved in history
  • History is excluded from iCloud synchronization and device backup
  • Delete one record or all history from the History screen
  • Remove the API key in Settings
  • Withdraw OpenAI transmission consent in Settings. Withdrawal does not automatically remove the API key
  • Erase OpenAI data-usage records from the Data Usage screen

The App cannot delete information already sent to OpenAI or OpenAI-side Usage and billing records. Use your own OpenAI account for those actions.

Read the Privacy Policy for full details.

Language and accessibility

Choose System, Japanese, or English for the App’s display. Normal screens show only the selected language. Operating-system permission dialogs and MultipeerConnectivity connection screens may follow the device’s system language instead.

You can change text size, horizontal or vertical writing, scrolling or automatic shrinking, and iPhone orientation. VoiceOver provides start and stop actions that do not require holding the screen. If text is clipped, return the device to portrait orientation or scroll without reducing your preferred text size.

Safety notice

Before recording, sending audio to OpenAI, or sharing nearby, tell every participant and obtain permission. Do not use these paths if you cannot confirm a participant’s permission. Automatic transcription can be wrong. The App is not a medical device, emergency-contact method, legal record, or guaranteed broadcast system. Do not rely on it alone for medical, emergency, contractual, financial, or other critical information.

Contact

For a bug or suggestion, describe what you noticed in the dedicated feedback page. You do not need to separately enter the app name, display language, category, device, OS, or email address. Individual replies are not normally provided.

For business, operational or other inquiries, and privacy requests, use Contact. A reply address is optional. Replies to ordinary inquiries are not guaranteed; requests under privacy law are handled in accordance with applicable law.

Submission is unavailable while a page says that intake is being prepared. Before submitting, read that page’s purpose, retention, deletion, and external-processing information. The App does not automatically attach audio, transcripts, API keys, or device information.

Never send an API key, authorization header, recording, conversation text, Apple ID password, or two-factor authentication code.
