Privacy

Last updated: September 5, 2026

Tsutawaru Moji (the “App”) is an iPhone and Apple Watch app that turns face-to-face conversation into readable text. This policy explains what information the App handles, when information leaves a device, how it is stored, and how it can be deleted.

Summary
  • On-device transcription does not send conversation audio to OpenAI or another external transcription service.
  • OpenAI API and Hybrid transcription are optional. Only after you explicitly consent to the current explanation of what is sent, where it goes, costs, and how to withdraw, choose one of those methods, and finish recording does the App send that recording directly to OpenAI using your own API key.
  • Before recording, sending audio to OpenAI, or sharing nearby, tell every conversation participant and obtain their permission. Do not use these paths when you cannot confirm a participant’s permission.
  • The App has no developer-operated server. It provides no mechanism for the developer to receive or remotely view your audio, transcript text, history, or API key.
  • The App uses no advertising, behavioral analytics, third-party crash-reporting SDK, or tracking.
1. On-device transcription

On-device mode uses Apple speech-recognition capabilities on a supported iPhone. Recording audio is processed in memory and is not stored in transcript history as an audio file. If on-device recognition is unavailable, the App does not silently switch to OpenAI.

Apple’s privacy policy and your device settings apply to information processed by Apple speech-recognition and operating-system services. The App requires on-device recognition and does not silently fall back to network recognition.

Only when you enable Apple Intelligence editing for On Device with All at the End does the App process the finalized transcript and button-specific instructions with Apple’s on-device Foundation Models. The transcript and instructions do not leave the device. If the feature is unavailable, fails, or returns an empty result, the App keeps the unedited transcript.

2. Transcription using OpenAI (optional)

Before OpenAI API or Hybrid transcription can be used, the App explains what is sent, the recipient, costs, OpenAI’s handling, and how to withdraw, then asks for explicit consent to the current explanation. If consent is absent, damaged, for an older explanation, or withdrawn, the App changes every OpenAI API and Hybrid input surface to On Device and does not begin recording or transmission for OpenAI.

Only when you have consented to the current explanation, select OpenAI API or Hybrid, and end a recording does the iPhone send the following information directly over HTTPS to https://api.openai.com/v1/audio/transcriptions:

  • The audio from that recording
  • The selected spoken language
  • The button-specific transcription instruction set by the user
  • Your own OpenAI API key, in the HTTPS authorization header

As part of ordinary internet communication, OpenAI also receives network metadata such as the source IP address, HTTP headers, and request time. The API key and submitted content may be associated with your OpenAI Project or account.

The App does not stream audio to OpenAI while you are recording, and it does not display partial text streamed from OpenAI. Hybrid displays an on-device draft while recording and sends the same utterance to OpenAI only after recording ends. Upload audio uses a speech-focused product setting of 24 kHz, mono, 48 kbps AAC. This is a product setting chosen to balance recognition quality and transfer size; it is not described as OpenAI’s published maximum useful audio quality.

You are responsible for OpenAI API charges and network data charges. A ChatGPT subscription and OpenAI API billing are separate. The App does not sell or manage OpenAI payment, balance, billing, or usage limits.

Use an OpenAI mode only after obtaining every participant’s permission, and do not submit medical information, authentication information, financial information, or other highly sensitive content. Anyone under 18 needs permission from a parent or legal guardian to use an OpenAI mode. Do not send audio or other personal information of children under 13 using this app’s OpenAI modes, including recordings made by an adult.

Information sent to OpenAI is governed by OpenAI’s terms and data practices. OpenAI’s first-party documentation, reviewed on September 4, 2026, states that API inputs and outputs are not used to train or improve its models unless the account holder explicitly opts in to data sharing. Its endpoint table lists no abuse-monitoring retention and no application-state retention for /v1/audio/transcriptions, the endpoint used by the App. This does not mean that OpenAI keeps no account, usage, or billing records. Policies and account settings can change; consult the current OpenAI API data controls documentation.

Downloading the App from the Japan storefront does not make OpenAI processing Japan-only. The App uses the global api.openai.com endpoint and does not guarantee that submitted content is processed or stored only in Japan. Availability of OpenAI regional storage or processing depends on your OpenAI agreement, Project settings, eligible region, and current terms.

Withdrawal or cancellation is a best-effort stop for a request that has already begun. It cannot recall submitted information or undo charges already incurred.

3. Your OpenAI API key

The App stores the API key in the iPhone Keychain only when the device has a passcode. It is configured not to sync through iCloud or migrate to another device. The App does not reveal the saved key again or store it in UserDefaults, transcript history, data-usage records, or ordinary logs. After the App is deleted and reinstalled, it removes an older App-specific Keychain item on first launch. Until it can confirm removal of that older item, it does not use any remaining key or allow key storage, reading, deletion, OpenAI recording, or OpenAI transmission.

OpenAI recommends that API keys not be deployed directly in mobile apps and instead be protected by a backend controlled by the key holder. Tsutawaru Moji uses a serverless BYOK (“bring your own key”) design and cannot provide security equivalent to that recommendation. Use a project key dedicated to this App, the narrowest available Restricted permissions, spending limits, regular Usage review, and prompt revocation when the key is no longer needed. Never send an API key to another person, a chat, email, or an ordinary note.

4. Apple Watch input

The Apple Watch app starts recording explicitly from an input surface using the selected interaction style. In Hold to Talk it uses the microphone until you release; in Tap to Start/Stop it uses the microphone until you tap the same surface again. It sends 16 kHz, mono, 16-bit PCM audio chunks through WatchConnectivity to the paired iPhone. “Near real time” refers to these audio chunks reaching the iPhone; it does not mean partial OpenAI captions are displayed in real time.

The iPhone protects the received audio in a temporary file and transcribes it using the method and language selected on the iPhone. On-device mode does not send it to OpenAI. In OpenAI API or Hybrid mode, only while current consent exists, the iPhone converts the completed recording to 24 kHz mono AAC at 48 kbps and sends it under the conditions in Section 2. The App attempts to delete temporary files after success, failure, or cancellation. If deletion fails, the App notifies you and tries again the next time it launches. An incomplete recording from a lost connection is handled by the same deletion process. Both apps must be open in the foreground and reachable.

5. Share with Nearby iPhones (experimental)

Only after the user confirms that every participant has given permission, both speaker and viewer record that confirmation in the App, the viewer selects a speaker, and the speaker accepts the invitation do the devices display a shared six-digit code. Text transmission remains disabled until both sides compare that code face to face and confirm that it matches. The App then sends confirmed portions during transcription or finalized transcript text directly to that verified peer. The connection uses a MultipeerConnectivity session with encryption required and rejects verification when multiple peers have the same display name.

This feature sends text, minimal state such as recording or processing status, and information needed to connect and mutually verify the peer. It does not send audio, saved history, or API keys. It uses no developer server, CloudKit, or user account. It supports one speaking iPhone and up to seven viewing iPhones (eight devices total) for nearby, foreground use. It does not provide remote, asynchronous, background, or reliable delivery to eight or more viewing iPhones (nine or more devices total). The six-digit code compares the two devices in that connection; it does not prove a person’s identity. Confirm the other device face to face.

The App cannot prevent a nearby recipient from taking screenshots or photos, copying text, or sharing it again. Ending sharing may not recover information the recipient has kept. The code does not guarantee how the recipient will use the information.

6. Information stored on the iPhone

Transcript history

The App stores finalized transcript text, creation time, and the transcription method used. Audio is not stored in history. History is excluded from iCloud synchronization and device backup and uses file protection so it cannot be read while the device is locked. You can delete individual records or all history. The App does not promise forensic erasure from underlying storage.

OpenAI data-usage records

For OpenAI API traffic, the App stores HTTP request and response byte counts, time, a Cellular / Wi-Fi and Other / Unknown classification, and a random identifier used to group transactions belonging to one logical API request. These records remain on the iPhone for up to two years. They do not contain audio, transcript text, or the API key, and you can erase them from the App.

The displayed totals include HTTP bodies and headers. The App adds together transfers from redirects and network-retry transactions that belong to one logical request, and records 4xx and 5xx responses when metrics are available. An operation canceled with zero bytes transferred is not recorded; bytes transferred before cancellation are recorded. If one logical request uses both Cellular and Wi-Fi and Other, it appears once in each interface row but once in the overall request count. Interface-row counts therefore may not add up to the overall count.

The totals do not include TLS overhead, transport-layer overhead, operating-system retransmissions, traffic from other apps, or the amount you are billed, and are not expected to match OpenAI Usage or a carrier bill. If saved records cannot be read, the App warns that the display may be incomplete and does not overwrite the original file until you explicitly erase the usage history. If saving new records fails, the App warns that the current values may be lost after relaunch. If erasing fails, the App leaves the on-device records unchanged and displays a warning.

Settings

The App stores settings such as display language, text size, writing direction, transcription method, and the date and policy version of consent to the current OpenAI explanation on the iPhone. Button-specific OpenAI instructions are stored in a dedicated file with file protection and exclusion from device backup. Display language and spoken transcription language are independent. The App does not translate between languages.

If an older version stored separate Japanese and English instructions, migration preserves backup copies of both in the same protected area without replacing existing button settings. These archived copies themselves are not used for ordinary display or transmission and survive restoring default settings. Separately, if no button settings exist, an older instruction may be migrated into an active button setting and used there. Deleting the App removes the archive as well. If migration fails, the original stored values are kept to avoid losing the instructions.

7. Temporary files and deletion

Temporary files for OpenAI uploads and Apple Watch input use file protection and are excluded from device backup. The App attempts to delete them after success, failure, cancellation, or timeout. If deletion fails, the App notifies you and retries files left in its dedicated temporary-audio areas at the next launch. The same launch sweep handles files left by an abnormal termination. If the sweep itself fails, the App notifies you and tries again at a later launch.

You can delete transcript history and data-usage records in the App. You can withdraw OpenAI transmission consent at any time in Settings. Withdrawal changes every input surface to On Device and prevents future OpenAI recording and transmission, but does not automatically remove the API key; use the separate key-removal action for that. Deleting the App removes its app-container data, but the App cannot delete information already sent to OpenAI or OpenAI-side Usage and billing records. Use your OpenAI account for those actions.

8. Permissions

The App requests the following permissions only for the relevant features:

  • iPhone and Apple Watch microphone: to capture speech
  • iPhone Speech Recognition: for on-device transcription
  • iPhone Local Network: to send transcript text directly to nearby iPhones

Operating-system permission dialogs and MultipeerConnectivity connection screens may follow the device’s system language rather than the display language selected inside the App.

9. Advertising, analytics, and tracking

The App contains no advertising SDK, behavioral analytics SDK, or third-party crash-reporting SDK. It does not track you across other companies’ apps or websites and has no App-specific remote logging service. Under Apple’s policies and your device settings, Apple may separately process App Store usage or diagnostics and may provide the developer with aggregated information or diagnostic reports.

Web support channels

External web pages open only when you select a support, public-policy, feedback, or Contact link. The App does not attach audio, transcripts, history, API keys, or device details to the URL or automatically submit an inquiry. Normal web browsing sends network information such as IP addresses and browser details to the hosting provider, GitHub, and to Google if a Google Form is displayed.

Dedicated Feedback uses one free-text field for bugs and suggestions, does not ask for a name or reply address, and normally provides no individual reply. Shared Contact handles business, operational and other inquiries, and privacy requests; a reply address is optional. Contact messages and addresses are not reused for Feedback AI classification or development issue reports.

Submitted information is used for the purpose of the selected channel. Read its retention, deletion, and external-processing notice before submitting. Submission remains disabled until the notices and intake are ready. Not entering a name does not mean that web network information does not exist.

10. Safety limitations

Automatic transcription can be wrong. Results vary with the device, how Apple Watch is worn, surrounding sound, connections, and OpenAI service availability. The App is not a medical device, emergency-contact method, legal record, or guaranteed broadcast system. Do not rely on the App alone for medical, emergency, contractual, financial, or other critical decisions.

11. Changes to this policy

If App features, external services, laws, or platform requirements change, this policy will be updated and its “Last updated” date will change. Material changes will be announced in the App or on the public support page.
